## 애플리케이션을 AWS에 배포 가능한 상태로 구축해야 하는 이유
운영 서버와 개발 서버는 별도의 AWS EC2를 구축해 운영해야 한다.
왜 AWS에 배포해야 할까? 로컬 개발 환경과 AWS 배포 환경을 동일하게 맞추면, `개발 환경에서는 잘 되는데 운영 환경에서는 안 된다` 문제를 줄일 수 있다
또 AWS에 배포를 해야 클라우드가 제공하는 기능을 이용해 규모가 커져도 안정적인 운영이 가능하다

## 애플리케이션 서버와 데이터베이스 서버를 분리해야 하는 이유
DB 서버를 퍼블릭 네트워크에서 분리하고 private subnet에 두면 외부에서 중요한 DB에 직접적인 공격을 막을 수 있다
서비스에는 민감한 개인 정보가 저장될 수 있고, 이를 private subnet에 두어 같은 보안그룹의 EC2에서만 접근할 수 있다면 비교적 안전하다

또, 애플리케이션 서버와 DB 서버가 같은 EC2에 있으면 여러 자원을 놓고 경쟁하게 된다. DB도 I/O 작업을 진행하고, 애플리케이션도 여러 I/O 작업을 진행할 수 있는데,
같은 서버에 둔다면 서로 경쟁하는 상황이 발생할 수 있고 여러 요청을 처리하기 어렵다고 생각한다

## 개발(dev)과 운영(prod)의 설정을 서로 독립적으로 관리·배포해야 하는 이유
운영 서버는 실제 사용자에게 제공되는 서버다. 개발 단계에서는 많은 문제가 발생할 수 있고, 독립적으로 관리/배포 되지 않으면 개발서버에서 발생한 문제가
운영에 영향을 줄 수 있다. 예를 들어 개발 서버에서 잘못된 로직으로 인해 OutOfMemory 같은 상황이 발생했을 때 운영 서버도 함께 죽을 수 있다
